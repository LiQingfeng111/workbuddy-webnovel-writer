# 世界书与大纲

## 原则

世界书回答「这个世界里什么恒定为真」，大纲回答「故事往哪走」。二者都是真源，但**只登记会被正文用到、或会约束未来章节的内容**；不写百科全书式的设定堆砌。每新增一条设定，都要能回答：它会在哪一章被读者看见？若答案未知，放进 `04-草稿区/灵感.md` 当候选。

## 世界书（`01-世界书/`）

### 人物.md

一人一节，人物卡字段：

```markdown
## 林砚｜主角
- 身份: 市立三中高二学生 / 夜间「清道夫」
- 目标: 查清姐姐失踪的真相
- 动机: 愧疚（当年替她值了那次班）
- 恐惧: 再次因为自己的选择害死身边人
- 能力边界: 每晚只能「回溯」一次，且不能超过 10 分钟
- 代价: 每次回溯丢失一段自己的记忆
- 语言习惯: 短句、少用感叹号、紧张时会重复对方最后两个字
- 关系网: 姐姐林汐（失踪）／陈叔（引路人，不信任）／周蔓（同班，知情）
- 当前状态: 第 12 章末，已失去「高中入学那天」的记忆
- 首次出场: 第 001 章
- 禁止写法: 不为救陌生人放弃查真相；不主动向周蔓炫耀能力
```

「能力边界」「代价」「禁止写法」是防 OOC 与战力崩的核心，必填。人物当前状态由 `05-账本/人物状态.md` 按章推进，人物卡里只保留最近一次快照与指向账本的链接。

### 势力与地点.md

每个势力记录：诉求、资源、内部派系、与主角的关系、不可越界的规则。每个地点记录：空间布局、可达方式、出现章节、随剧情发生的变化（被毁、封锁等变化要记入事实账本）。

### 规则与力量体系.md

用可检验的句式写规则，避免「越强越厉害」：

- 能力如何获得、如何升级、上限在哪里；
- 使用代价、冷却、失效条件；
- 世界层面对所有角色一视同仁的硬规则（例如「回溯不能改变他人记忆」）；
- 明确列出「本书不存在的解法」，防止中期用新设定强行圆场。

新增规则时做一次影响分析：列出受影响的大纲条目、已定稿章节、账本事实，交给作者裁决，不自动改写。

### 时间线.md

- 全书起始时间与纪年方式；
- 每章对应的故事内时间（相对天数即可），避免「三个月后」反复出现却没人推进；
- 与真实节日、季节、角色年龄相关的硬约束；
- 只记录已发生（已定稿）的时间推进，计划中的放在卷纲。

## 大纲（`02-大纲/`）

### 总纲.md

一页以内：核心冲突、主线三到五个大转折、主要支线及其收束位置、预计卷数与每卷的功能（立人设 / 升维 / 转折 / 收网）、结局方向。总纲不写具体章节。

### 卷NN.md

每卷一个文件，包含卷纲与逐章细纲：

```markdown
# 卷01 · 夜里多出来的一分钟

## 卷纲
- 卷目标: 主角接受「清道夫」身份，第一次触及姐姐失踪的线索
- 主冲突: 陈叔要他听话 vs 他要自己查
- 节奏: 1–5 立日常与规则 / 6–12 第一次连环事件 / 13–20 卷末反转
- 章数窗口: 20（窗口用尽不等于整卷完成）
- 卷末状态: 主角失去一段记忆；周蔓知道能力存在；青铜钥匙首次出现
- 必须回收的伏笔: F001、F003

## 章纲

### 第 012 章 · 第十分钟
- POV: 林砚（第三人称有限）
- 场景: 旧教学楼天台，雨夜，故事内第 19 天
- 出场: 林砚、陈叔
- 本章目标: 主角用回溯救下陈叔，却发现代价是入学那天的记忆
- 冲突与转折: 陈叔隐瞒了回溯的真实代价 → 主角当场识破
- 爽点 / 钩子: 章末出现姐姐的字迹「别再用第二次」
- 伏笔动作: 推进 F003（姐姐字迹）；埋设 F007（陈叔的旧伤）
- 承接前章: 第 011 章末，陈叔失联，雨开始下
- 留给下章: 周蔓为什么出现在监控里
- 必写事实: 回溯代价 = 丢失一段记忆，且被主角亲口确认
- 预计汉字数: 2000
```

**细纲未确认前不起草正文**。章纲是备料与审读的对照基准；起草时若偏离，要么改细纲（留痕），要么在审读中列为发现项。

### 节奏工具

- **钩子**：章末制造一个未回答的问题，须在台账中登记，防止只埋不收。
- **微兑现**：每章至少给读者一个小回报（信息、胜利、关系推进、笑点），不要全章都在铺垫。
- **债务**：向读者承诺但尚未兑现的事项，记入 `05-账本/伏笔台账.md` 的「未回收」区，卷末统一对账。
- **窗口**：每卷的章数只是规划区间；窗口耗尽时先核对卷目标是否达成，再决定加章或收卷，不自动判定完成。

## 影响分析（改设定时必做）

任何对契约、世界书、大纲的实质修改，先输出一份只读报告：

1. 改了哪一条，原文与新文分别是什么；
2. 受影响的细纲条目（卷号 + 章号）；
3. 受影响的已定稿章节（章号 + 具体段落）；
4. 受影响的事实账本、伏笔台账、人物状态条目；
5. 建议处置（改稿 / retcon / 作者保留现状），**等作者决定后再动手**。

禁止因为「上游改了」就自动重写下游，也不要把影响分析报告当成已执行的修改。
